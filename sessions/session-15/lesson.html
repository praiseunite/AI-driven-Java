1. JDK Releases & LTS

Java ships a feature release every six months (21, 22, 23, 24, 25…). Every few years one is marked LTS (Long-Term Support) with years of updates — JDK 21 and JDK 25 are LTS releases. Enterprises target LTS; this course standardises on JDK 25.

ℹ️ "Preview" features

New language features often arrive as preview (compile with --enable-preview) for a release or two, then become permanent. The features below are finalised in the JDK 21–25 range.

2. Virtual Threads (JDK 21)

A classic Thread maps 1:1 to an operating-system thread — heavy, so you can only have a few thousand. A virtual thread is scheduled by the JVM onto a small pool of OS threads, so you can run millions. Great for servers handling many concurrent, mostly-waiting requests.

JavaVirtualThreads.java
// start one virtual thread
Thread t = Thread.ofVirtual().start(() -> System.out.println("hi from a virtual thread"));
t.join();

// spawn 10,000 — cheap
for (int i = 0; i < 10_000; i++) {
    workers[i] = Thread.ofVirtual().start(() -> doWork());
}
for (Thread w : workers) w.join();

// idiomatic: one virtual thread per task via an executor
try (var pool = Executors.newVirtualThreadPerTaskExecutor()) {
    for (Runnable task : tasks) pool.submit(task);
}   // pool.close() waits for all tasks
💡 The mental shift

With virtual threads you no longer ration threads or juggle callbacks — write simple blocking code, one thread per task, and let the JVM handle scale.

3. Sealed Types (JDK 17)

sealed restricts which classes may extend/implement a type. The compiler then knows the full set — enabling exhaustive switch with no default.

Java
sealed interface Shape permits Circle, Rectangle, Triangle {}
record Circle(double radius)        implements Shape {}
record Rectangle(double w, double h) implements Shape {}
record Triangle(double base, double height) implements Shape {}

4. Record Patterns & Pattern Matching for switch (JDK 21)

A switch can match on type, add a when guard, and deconstruct a record into its components in one step.

JavaRecordPatterns.java
static double area(Shape s) {
    return switch (s) {
        case Circle c                      -> Math.PI * c.radius() * c.radius();
        case Rectangle(double w, double h) -> w * h;        // deconstructed
        case Triangle(double b, double h)  -> 0.5 * b * h;
    };  // no default: Shape is sealed, all cases covered
}

static String describe(Object o) {
    return switch (o) {
        case Integer i when i < 0 -> "negative int";        // guarded pattern
        case Integer i            -> "int " + i;
        case String str           -> "string of length " + str.length();
        case null                 -> "null";                 // switch can handle null now
        default                   -> "something else";
    };
}
💡 This replaces instanceof ladders

The Session 12 refactor ("if (x instanceof A) ... else if (x instanceof B)") becomes a clean, exhaustive switch — and the compiler tells you if you miss a case.

5. Sequenced Collections (JDK 21)

Ordered collections now have a uniform first/last/reverse API:

Java
List<String> list = new ArrayList<>(List.of("a", "b", "c", "d"));

list.getFirst();     // "a"      (was list.get(0))
list.getLast();      // "d"      (was list.get(list.size() - 1))
list.addFirst("Z");  // [Z, a, b, c, d]
list.removeLast();   // [Z, a, b, c]
list.reversed();     // a reversed VIEW

8. Prompt Engineering for Code

A good code prompt has four parts. Miss one and the output drifts.

  1. Role & level — "You're helping a Java beginner (Week 4)…"
  2. Concrete task — "Write a method groupByFirstLetter(List<String>) returning Map<Character, List<String>>."
  3. Constraints — "Use only concepts through Session 14 (streams OK, no external libraries). Target Java 25."
  4. Output shape — "Give the method plus a 3-line example call and expected output. Explain each stream step in one sentence."
🧩 Iterate, don't accept blindly

"That uses a Collector I haven't learned — redo it with a plain loop."  ·  "It doesn't compile: 'cannot find symbol reversed()'. What Java version is that from?"  ·  "Add a test for the empty-list case."

9. Reviewing AI Output — a checklist

  1. Compile & run it. The compiler and the output are ground truth.
  2. Read every line. If you can't explain one, ask the AI to explain it or simplify — do not submit it.
  3. Check the API is real. Hallucinated methods (list.sortAscending(), String.reverse()) won't compile; verify against the Java 25 docs.
  4. Test the edges. Empty input, null, one element, huge input, negative numbers.
  5. Look for silent bugs. Off-by-one, swallowed exceptions, == on objects, integer division, wrong rounding.
  6. Match the codebase. Naming, formatting, error-handling style, no stray libraries.

10. Ethics, Licensing & Security

⚠️ Four things to keep in mind
  • Academic honesty: assignments measure your understanding. Use AI to learn; write and be able to explain your own submissions. Pasting AI-generated assignments is misconduct.
  • Licensing: generated code can resemble training data. For real projects, treat large verbatim blocks with caution and prefer AI for structure and explanation over wholesale copying.
  • Confidentiality: don't paste secrets, credentials, or proprietary/customer code into a public assistant. Use company-approved tools for company code.
  • Security: AI happily writes SQL-injectable queries, weak crypto, and unvalidated input handling. Review security-sensitive code especially hard.

11. Executive Quick-Recap & Cheat Sheet

⚡ The 30-Second Mental Model

Java ships every 6 months; LTS (21, 25) is what you target. Virtual threads: millions of cheap threads, one per task. Sealed types + record patterns in switch give exhaustive, deconstructing matches that replace instanceof ladders. Sequenced collections add getFirst/getLast/reversed. For AI: prompt with role + task + constraints + output shape; then compile, read every line, verify the API, test edges — never ship code you can't explain.

LTS

Long-Term Support JDK release (21, 25) with multi-year updates.

Virtual thread

A lightweight thread the JVM multiplexes onto few OS threads; millions are cheap.

sealed

Restricts which classes may extend/implement a type (permits).

Pattern matching for switch

Match on type, guard with when, handle null, be exhaustive.

Record pattern

Deconstruct a record into its components in a case.

12. Summary & Interactive Self-Checks

🤖 Ask Your AI Tutor

Try these — and practise reviewing what comes back:

  • "Write a sealed Result type with Ok(value) and Err(message) records, and a switch that handles both. Target Java 25."
  • "Show classic threads vs a virtual-thread-per-task executor for 1,000 tasks, and explain the difference."
  • "Give me a deliberately buggy 20-line Java method and let me find the 3 bugs; then tell me if I got them."
❓ Q1: Why can millions of virtual threads run when only a few thousand platform threads can?
Answer: Virtual threads don't each own an OS thread; the JVM parks a waiting one and reuses a small pool of carrier OS threads. They cost bytes, not megabytes.
❓ Q2: Why does a switch over a sealed type not need a default?
Answer: The compiler knows every permitted subtype, so if you cover them all the switch is provably exhaustive — and it errors if you miss one.
❓ Q3: An AI gives you code using list.getFirst() and your build fails with "cannot find symbol". Likely cause?
Answer: Your project targets a JDK older than 21 (sequenced collections). Check the project SDK / language level, or ask the AI for a pre-21 version.
❓ Q4: What is the single rule for submitting AI-assisted code as your own work?
Answer: You must understand and be able to explain every line. Use AI to learn and draft; the submitted work — and the understanding — must be yours.
