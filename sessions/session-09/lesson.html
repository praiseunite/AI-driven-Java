Session 9: Inheritance and Polymorphism

Real systems have families of related types: a Manager is an Employee; a Circle is a Shape. Inheritance lets one class build on another without copy-paste. Polymorphism lets one line of code — shape.area() — do the right thing for whatever shape it actually holds.

1. The "is-a" Relationship

Use inheritance only when the subclass genuinely is a kind of the superclass. A Dog is an Animal. A SavingsAccount is a BankAccount. If the sentence "X is a Y" sounds wrong, you want a field ("has-a"), not inheritance.

🧬 Analogy: a family recipe

The superclass is grandma's base bread recipe. A subclass is "the same, plus olives" — you don't rewrite the whole recipe, you say "start from the base, then add this step". You can also replace a step (bake at a different temperature) — that is overriding.

2. extends & Inherited Members

Java
class Animal {
    protected String name;                 // visible to subclasses
    Animal(String name) { this.name = name; }
    String speak() { return name + " makes a sound"; }
}

class Dog extends Animal {                 // Dog gets name + speak() for free
    Dog(String name) { super(name); }      // call Animal's constructor
    void fetch() { System.out.println(name + " fetches the ball"); }
}

Dog d = new Dog("Rex");
d.fetch();                 // Dog's own method
System.out.println(d.speak());   // inherited from Animal -> "Rex makes a sound"

A subclass inherits all public and protected members. It does not inherit private members (though they still exist inside the object) and it does not inherit constructors.

ℹ️ Every class extends Object

If you write no extends, your class implicitly extends java.lang.Object — which is why every object already has toString(), equals(), and hashCode(). Java has single inheritance: a class has exactly one direct superclass. (Multiple interfaces come in Session 10.)

3. super

super refers to the superclass part of the current object. Two uses:

  • super(...) — call a superclass constructor. Must be the first statement of the subclass constructor. If you don't write it, Java inserts super() automatically (and that fails if the superclass has no no-arg constructor).
  • super.method() — call the superclass's version of a method you have overridden, so you can extend it rather than fully replace it.
Java
class Manager extends Employee {
    private final double bonus;

    Manager(String name, double baseSalary, double annualBonus) {
        super(name, baseSalary);              // run Employee's constructor first
        this.bonus = annualBonus;
    }

    @Override
    double monthlyPay() {
        return super.monthlyPay() + bonus / 12;   // base pay PLUS the bonus share
    }
}

4. Method Overriding

A subclass overrides a method by declaring one with the same signature (name + parameter types) as the superclass's. From then on, calling that method on such an object runs the subclass version.

Java
class Animal {
    String speak() { return name + " makes a sound"; }
}
class Dog extends Animal {
    @Override
    String speak() { return name + " says Woof"; }   // replaces Animal's version for Dogs
}
💡 Always write @Override

It is optional, but it makes the compiler check that you really are overriding something. Misspell the name or get a parameter type wrong and you'll get an error instead of a silently-new method that never gets called.

6. Polymorphism & Dynamic Dispatch

A superclass variable can point at any subclass object. When you call an overridden method through it, Java runs the version belonging to the object's actual type — decided at run time. This is dynamic dispatch, and it is what makes polymorphism useful.

JavaAnimalDemo.java
Animal[] zoo = { new Dog("Rex"), new Cat("Milo"), new Animal("Thing") };

for (Animal a : zoo) {
    System.out.println(a.speak());
}
// Output:
//   Rex says Woof        <- Dog.speak()
//   Milo says Meow       <- Cat.speak()
//   Thing makes a sound  <- Animal.speak()
💡 Why this matters

The loop knows nothing about dogs or cats. Add a Cow class tomorrow and this code prints "Moo" with no change. Polymorphism lets you write code against the general type and extend the specifics later.

7. abstract Classes

Sometimes the superclass is a concept with no sensible standalone instance — a "Shape" that isn't a specific shape. Mark it abstract: it cannot be instantiated, and it may declare abstract methods (no body) that every concrete subclass must implement.

Java
abstract class Shape {
    abstract double area();                 // no body — subclasses must supply one

    void describe() {                        // a normal method, using the abstract one
        System.out.printf("%s area %.2f%n", getClass().getSimpleName(), area());
    }
}

class Circle extends Shape {
    private final double r;
    Circle(double r) { this.r = r; }
    @Override double area() { return Math.PI * r * r; }
}

// new Shape();          // COMPILE ERROR: Shape is abstract and cannot be instantiated
Shape s = new Circle(3); // fine — a Circle IS a Shape
s.describe();            // "Circle area 28.27"
ℹ️ Abstract class vs interface (preview)

An abstract class can hold state (fields) and finished methods, and a class extends only one. An interface (Session 10) is a pure contract that a class can implement many of. Use an abstract class for "a partly-built base type".

8. Overriding Object Methods

Every class inherits these from Object; overriding them makes your type behave sensibly:

MethodDefaultOverride to…
toString()ClassName@1b6d3586return a readable description
equals(Object)== (same object)compare by contents
hashCode()identity-based numbermatch equals — equal objects must return equal hash codes
JavaPoint.java
import java.util.Objects;

class Point {
    private final int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Point)) return false;
        Point p = (Point) o;
        return x == p.x && y == p.y;
    }

    @Override
    public int hashCode() { return Objects.hash(x, y); }

    @Override
    public String toString() { return "(" + x + ", " + y + ")"; }
}

new Point(2, 3).equals(new Point(2, 3));   // true  (contents)
new Point(2, 3) == new Point(2, 3);        // false (different objects)
💡 Let the IDE write these

IntelliJ: Alt+Insert → equals() and hashCode(), and toString(). Always generate equals and hashCode together.

9. final & instanceof

  • final method — a subclass cannot override it.
  • final class — cannot be subclassed at all (String, Integer).
  • instanceof — tests an object's type before a cast:
Java
for (Animal a : zoo) {
    if (a instanceof Dog) {
        Dog d = (Dog) a;      // safe cast — we just checked
        d.fetch();
    }
}

// Modern "pattern" form (Java 16+):
if (a instanceof Dog d) {
    d.fetch();                // d is already the cast Dog
}

Reach for polymorphism (an overridden method) first; use instanceof only when a subtype has behaviour the base type genuinely doesn't.

10. Common Pitfalls

🚨 super(...) not first

The call to a superclass constructor must be the very first statement of the subclass constructor. Anything before it is a compile error.

🚨 Superclass has no no-arg constructor

If Animal only has Animal(String), a subclass constructor that doesn't call super(name) won't compile — Java's implicit super() has nothing to call.

🚨 "Overriding" with a different signature

String speak(int volume) in the subclass does not override String speak() — it's an unrelated overload. @Override would have caught this.

🚨 equals without hashCode

Override one, override the other. Objects that are equals but have different hash codes break HashMap / HashSet.

🚨 ClassCastException

(Dog) someCat compiles but throws at run time. Guard casts with instanceof.

11. Executive Quick-Recap & Cheat Sheet

⚡ The 30-Second Mental Model

class Sub extends Super — Sub gets Super's public/protected members. super(...) (first line) runs the parent constructor; super.m() calls the parent's method. Overriding = same signature in a subclass, chosen at run time by the object's real type (dynamic dispatch). abstract classes can't be instantiated and can demand methods. Override toString/equals/hashCode (the last two together) for value-like types.

Core Syntax at a Glance

Java Cheat Sheet
abstract class Payment {
    protected final double amount;
    Payment(double amount) { this.amount = amount; }
    abstract double fee();                        // subclasses must define
    final double total() { return amount + fee(); }   // cannot be overridden
}

class CardPayment extends Payment {
    CardPayment(double amount) { super(amount); }
    @Override double fee() { return amount * 0.029 + 0.30; }
}

class CashPayment extends Payment {
    CashPayment(double amount) { super(amount); }
    @Override double fee() { return 0; }
}

Payment[] batch = { new CardPayment(100), new CashPayment(100) };
for (Payment p : batch) System.out.printf("%.2f%n", p.total());   // 103.20 then 100.00

Plain-English Glossary

Inheritance

A class reusing and extending another's members via extends.

Superclass / subclass

The parent being extended / the child extending it.

is-a

The test for using inheritance: "a Dog is an Animal" is true.

super

super(...) calls the parent constructor; super.m() the parent method.

Overriding

A subclass redefining a superclass method with the same signature.

Polymorphism

One reference type, many possible object types; the right method runs automatically.

Dynamic dispatch

Choosing the overridden method at run time based on the object's real class.

abstract

A class that can't be instantiated; an abstract method has no body and must be implemented.

instanceof

Tests whether an object is (a subtype of) a given type, before casting.

equals / hashCode

Override together so value-equal objects also hash equally.

❓ Q1: Animal a = new Dog("Rex"); a.speak(); — whose speak() runs?
Answer: Dog's. The method is chosen at run time by the object's real type (dynamic dispatch), not by the variable's declared type.
❓ Q2: Where must super(name) appear in a subclass constructor?
Answer: As the first statement. If omitted, Java inserts super(), which fails when the superclass has no no-arg constructor.
❓ Q3: Can you write new Shape() if Shape is abstract?
Answer: No — abstract classes cannot be instantiated. You instantiate a concrete subclass and can store it in a Shape variable.
❓ Q4: You override equals but not hashCode. What breaks?
Answer: Hash-based collections (HashSet, HashMap). Two "equal" objects can land in different buckets, so lookups miss.
