🧠 The Whole Journey, in one breath

Source code (.java) is compiled by javac to bytecode (.class), run by the JVM. Data lives in variables (primitives on the stack, objects on the heap) and moves through operators. Control flow (if/switch, loops) decides what runs. You model the domain as classes — state + behavior, private fields — organised by inheritance and interfaces, kept in collections, protected by exception handling, and processed with streams. Dates use java.time; modern syntax (records, switch expressions, var, patterns) removes boilerplate. And you use AI to learn and draft — never to submit what you can't explain.

3. Professional Code-Review Checklist

Run this over your own code before you call it done — and over any code an AI hands you.

  1. Does it compile and run? Zero warnings. Run the happy path and at least one failure path.
  2. Correctness: off-by-one (< vs <=), integer division, wrong rounding, == on objects instead of .equals(), null handling.
  3. Encapsulation: fields private; state changes only through validating methods; constructors leave objects valid.
  4. Naming: classes = nouns (PascalCase), methods = verbs (camelCase), constants UPPER_SNAKE. No x, data, temp2.
  5. Methods do one thing and return results rather than printing them where possible.
  6. Exceptions: specific catches, never empty, not used for normal flow; resources in try-with-resources.
  7. Duplication: repeated blocks → a method; type-check ladders → polymorphism.
  8. Comments explain why, not what. The code says what.
  9. Formatting: consistent indentation (Ctrl+Alt+L in IntelliJ), one statement per line.

4. The Capstone Project

🏢 Brief: Campus Bookstore Console App

Build a single console application, BookstoreApp.java, that manages a small bookstore: an inventory of books, customer orders with discounts, and stream-powered sales reports. It must demonstrate, concretely, a feature from most of the course.

💡 The checkout pattern to notice

checkout builds and validates every line item first, and only then subtracts stock and records the order. If any line fails, it throws and nothing changes — the order is all-or-nothing. That is the exception-handling discipline from Session 11 applied to real state.

6. Final Assessment Prep

The Session 16 Final Assessment is comprehensive — 20 questions across all 16 sessions, including "what does this code print?" items. To prepare:

  • Re-take each session's post-quiz; target 80%+.
  • Re-run every solution/ program and predict the output before you run it.
  • Trace three loops and one recursive method by hand.
  • Explain, out loud, the difference between: overriding/overloading, checked/unchecked, Period/Duration, array/ArrayList, abstract class/interface, ==/.equals().

7. Where to Go Next

  • Build things. A CLI todo app, a text adventure, a small REST client. Volume beats theory now.
