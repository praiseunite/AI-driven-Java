Session 7: Modifiers and Packages

As programs grow past one file, you need to control who can see what (access modifiers), share data that belongs to a whole class rather than one object (static), organise code into folders (packages), and ship it as a single runnable file (a JAR).

1. The Four Access Levels

An access modifier on a field or method decides which other code may touch it. From most open to most closed:

ModifierSame classSame packageSubclass (other pkg)Anywhere
public✅✅✅✅
protected✅✅✅❌
(none) "package-private" / default✅✅❌❌
private✅❌❌❌
ℹ️ "Default" is not a keyword

Writing no modifier at all gives package-private access — visible only to code in the same package. There is no default keyword for this (that word means something else, in switch and interfaces).

2. Applying Access Modifiers

Java
public class Account {
    public String owner;          // anyone can read/write
    protected double balance;      // this package + subclasses
    double branchCode;             // this package only (no modifier)
    private String pin;            // only inside Account

    private boolean checkPin(String attempt) {   // internal helper — hidden
        return pin.equals(attempt);
    }

    public boolean withdraw(double amount, String pinAttempt) {  // the public door
        if (!checkPin(pinAttempt) || amount > balance) return false;
        balance -= amount;
        return true;
    }
}
💡 The default you should reach for

Fields private. Methods public only if outside code truly needs them, private otherwise. Start closed and open up deliberately — it is far easier than discovering later that everything depends on a field you wanted to change.

On a top-level class, only public or (none) are allowed. A public class must sit in a file of the same name (Session 1).

3. static: Class Members vs Instance Members

A normal (instance) field belongs to each object. A static field belongs to the class itself — there is exactly one copy, shared by every object and reachable without any object at all.

Java
class Robot {
    static int totalBuilt = 0;   // ONE shared copy
    int id;                      // each Robot has its own

    Robot() {
        totalBuilt++;            // bump the shared counter
        id = totalBuilt;
    }

    static int getTotalBuilt() { return totalBuilt; }   // static method
}

new Robot(); new Robot(); new Robot();
System.out.println(Robot.getTotalBuilt());   // 3  — called on the CLASS, no object needed

main is static for exactly this reason: the JVM must call it before any object exists.

4. static Gotchas

🚨 A static method cannot use this or instance fields

There is no "current object" in a static method. Referring to an instance field from static code gives "non-static field cannot be referenced from a static context". Pass what you need in as a parameter, or make the method non-static.

💡 The utility-class pattern

A class that is only static helpers (like Math) is never meant to be instantiated. Give it a private constructor so new MathUtils() won't compile.

5. final

  • final variable / field — a constant; assign once, never again. Combine with static for a class-wide constant: public static final double VAT_RATE = 0.075;.
  • final method — cannot be overridden by a subclass (Session 9).
  • final class — cannot be extended at all (e.g. String is final).
Java
public class Circle {
    public static final double PI = 3.14159;   // shared constant
    private final double radius;                // set once, in the constructor

    public Circle(double radius) {
        this.radius = radius;    // allowed — first and only assignment
    }
    // radius = 5;  // anywhere else -> compile error: cannot assign a value to final variable
}

6. Packages — Why & How

A package is a named folder of related classes. It does three jobs: groups code that belongs together, prevents name clashes (your Timer vs someone else's Timer), and forms an access boundary (package-private).

Javacom/aptech/util/TextTools.java
package com.aptech.util;      // FIRST line of the file

public class TextTools {
    public static String repeat(String s, int n) {
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < n; i++) sb.append(s);
        return sb.toString();
    }
}
⚠️ Folder path must match the package name

package com.aptech.util; means the file lives at com/aptech/util/TextTools.java. IntelliJ does this for you when you create the package; by hand, you make the folders yourself.

7. Naming & import

Convention: reverse your organisation's domain, all lowercase — com.aptech.util, org.example.billing. This keeps package names globally unique.

Java
import com.aptech.util.TextTools;     // now usable by its short name
import java.util.ArrayList;
import java.util.*;                   // everything in java.util (not sub-packages)

// Or skip the import and use the fully-qualified name inline:
java.util.Scanner in = new java.util.Scanner(System.in);
ℹ️ java.lang is always imported

String, System, Math, Integer, Object live in java.lang, which every file imports automatically — that is why you have never had to import them.

8. Compiling & Running with Packages

▶ Two ways

In IntelliJ: nothing changes — right-click the class with main → Run. The IDE handles paths and the classpath.

In the terminal (from the folder that contains the com folder):

Terminal
javac com/aptech/util/TextTools.java PackageMain.java
java PackageMain

# If PackageMain itself were in a package, e.g. com.aptech.app:
# java com.aptech.app.PackageMain

9. Building an Executable JAR

A JAR ("Java ARchive") is a single ZIP file bundling all your .class files (and resources). An executable JAR also records which class holds main, so it can be launched directly.

In IntelliJ IDEAIn the terminal
File → Project Structure → Artifacts → + → JAR → From modules with dependencies → pick the main class → OK. Then Build → Build Artifacts → Build. The JAR appears under out/artifacts/. 
javac -d out $(find . -name "*.java")
jar --create --file app.jar \
    --main-class PackageMain -C out .
java -jar app.jar
ℹ️ The manifest

Inside every JAR is META-INF/MANIFEST.MF. --main-class writes a Main-Class: line into it; that is what java -jar reads to know where to start.

10. Common Pitfalls

🚨 package line not first

The package declaration must be the very first line of code (comments are fine above it). Otherwise: "class, interface, or enum expected".

🚨 Folder doesn't match package

package com.aptech.util; in a file that is not under com/aptech/util/ → the class won't be found at run time.

🚨 Calling an instance method from static main

public static void main(...) { doStuff(); } where doStuff() is non-static → "non-static method cannot be referenced from a static context". Make doStuff static, or create an object and call it on that.

🚨 java -jar app.jar says "no main manifest attribute"

The JAR has no Main-Class: line. Rebuild it specifying the main class (--main-class, or the IntelliJ artifact dialog).

11. Executive Quick-Recap & Cheat Sheet

⚡ The 30-Second Mental Model

Access: public > protected > package-private > private. Fields private, expose methods. static = belongs to the class, one copy, no object needed (counters, Math-style helpers). final = assign once. A package is a named folder (path must match); import or fully-qualify to use one. A JAR bundles .class files; an executable one names its main class and runs with java -jar.

Core Syntax at a Glance

Java Cheat Sheet
package com.aptech.bank;              // first line; folder com/aptech/bank/

import java.util.ArrayList;

public class Bank {
    public static final double VAT = 0.075;   // shared constant
    private static int accountCount = 0;      // shared counter
    private final String name;                // per-object, set once

    public Bank(String name) {
        this.name = name;
        accountCount++;
    }

    public static int getAccountCount() { return accountCount; }  // no object needed
    public String getName() { return name; }                       // instance method
}

// Bank.getAccountCount();   // via the class
// new Bank("Apex").getName();

Plain-English Glossary

public

Visible to all code everywhere.

protected

Visible in the same package and to subclasses.

package-private (no modifier)

Visible only within the same package.

private

Visible only inside the same class.

static

Belongs to the class, not an instance — one shared copy, callable without an object.

final

Assign-once variable / non-overridable method / non-extendable class.

Package

A named folder grouping related classes; declared with package.

import

Lets you use a class from another package by its short name.

Fully-qualified name

Package + class, e.g. java.util.Scanner.

JAR

A ZIP of compiled classes; executable if its manifest names a Main-Class.

Manifest

META-INF/MANIFEST.MF inside a JAR; holds metadata like the main class.

❓ Q1: Which access level means "visible only within the same package"?
Answer: Package-private — you get it by writing no modifier. There is no default keyword for it.
❓ Q2: A static int count is incremented in a constructor. Three objects are created. What is count?
Answer: 3. There is one shared copy of a static field; each constructor call bumps the same variable.
❓ Q3: package com.aptech.util; — where must the .java file live?
Answer: Under com/aptech/util/. The folder path must mirror the package name exactly.
❓ Q4: java -jar app.jar → "no main manifest attribute". Cause?
Answer: The JAR's manifest has no Main-Class: entry. Rebuild specifying which class holds main.
