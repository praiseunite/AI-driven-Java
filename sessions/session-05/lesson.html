Session 5: Classes, Objects, and Methods

Until now you have used classes only as a container for main. Today classes become the point. You will design your own data types — a BankAccount, a Car, a Student — that bundle data together with the operations that belong to it. This is Object-Oriented Programming, and it is what the rest of the course is built on.

🧠 Memory Booster: Flashback to Week 1
  • main is a method — public static void main(String[] args). Today the words static, void, parameters, and return finally make full sense.
  • String is a reference type — a String variable holds an address to an object on the heap. Every class you write today creates reference types that work the same way.
  • Structured vs OOP (Session 1) — structured code keeps data and functions apart; OOP bundles them. Today you build that bundle.

1. Why Objects?

Imagine modelling a bank with plain variables: double adaBalance, double bobBalance, String adaOwner… and free-standing methods deposit(???), withdraw(???). Which balance does withdraw change? You have to pass it in and hope nobody edits the wrong variable. With 10,000 accounts this collapses.

An object keeps one account's data and its operations in a single unit. ada.withdraw(30) can only touch Ada's balance. The data and the code that is allowed to change it travel together.

🍪 Analogy: cookie cutter and cookies

A class is the cookie cutter: it defines the shape (what fields and methods every cookie has). An object is an actual cookie stamped from it. One cutter, many cookies — each with its own sprinkles (its own field values).

3. Fields (State) & Methods (Behavior)

Fields (also called instance variables or attributes) are variables declared directly inside the class. Every object gets its own copy. Methods are the operations. Inside a method, writing a field's name refers to this object's field.

Java
class Counter {
    int count;                 // field — each Counter has its own

    void increment() {
        count++;               // means: this object's count
    }

    int value() {
        return count;
    }
}

Counter a = new Counter();
Counter b = new Counter();
a.increment();
a.increment();
b.increment();
System.out.println(a.value());   // 2
System.out.println(b.value());   // 1  — b is a separate object
ℹ️ Default field values

Unlike local variables (which must be initialised before use), fields get automatic defaults: 0 for numbers, false for boolean, '' for char, and null for any reference type (including String).

4. new, References, and null

new Car() does three things: allocates a fresh object on the heap, runs its constructor, and returns the object's address. The variable on the left stores that address — it is a reference, not the object itself.

JavaReferences point; they don't copy
Car x = new Car();
x.model = "Corolla";

Car y = x;          // y copies the ADDRESS, not the car
y.model = "Mustang";

System.out.println(x.model);   // "Mustang"  — x and y point at the SAME object
🚨 null and NullPointerException

A reference that points at no object holds null. Calling a method or reading a field through it crashes with NullPointerException: 

Car z;                  // z is null (if it's a field) / uninitialised (if local)
z.accelerate(10);       // NullPointerException — there is no object to talk to

Fix: assign an object first — z = new Car();.

5. Constructors & this

A constructor is a special method that runs once, at new time, to set an object up. It has the same name as the class and no return type.

Java
class BankAccount {
    private String owner;
    private double balance;

    // constructor: same name as class, no return type
    public BankAccount(String owner, double openingBalance) {
        this.owner = owner;              // this.owner = the field
        this.balance = openingBalance;   // owner (no this) = the parameter
    }
}

BankAccount ada = new BankAccount("Ada", 100.00);
💡 What is this?

this means "the object this method is running on". You need it when a parameter has the same name as a field: this.owner is the field, owner is the parameter. If the names differ, this is optional.

ℹ️ The default (no-arg) constructor

If you write no constructor, Java gives you a hidden empty one, so new Car() works. The moment you write any constructor, that free one disappears — if you still want new Car(), write it yourself.

}

⚠️ Return is not print

return x; hands a value back to the caller. System.out.println(x); shows it on screen. A method that only prints cannot be reused in a calculation. Prefer returning a result and letting the caller decide what to do with it.

Local variable scope: a variable declared inside a method (or a { } block) exists only there. Parameters are local variables too.

7. Method Overloading

Two or more methods may share a name if their parameter lists differ (in number or type). The compiler picks the matching one by the arguments you pass. The return type alone is not enough to tell them apart.

Java
int add(int a, int b)            { return a + b; }
int add(int a, int b, int c)     { return a + b + c; }
double add(double a, double b)   { return a + b; }

add(2, 3);        // -> 5   (first version)
add(2, 3, 4);     // -> 9   (second)
add(2.5, 3.5);    // -> 6.0 (third)

8. Constructor Overloading & this(...)

Constructors can be overloaded the same way. To avoid repeating setup code, one constructor can call another with this(...) — which must be the first statement.

Java
class StudentRecord {
    private String name, track;
    private int score;

    public StudentRecord(String name, String track, int score) {
        this.name = name;
        this.track = track;
        this.score = score;
    }

    // "no score yet" -> delegate to the full constructor with a default
    public StudentRecord(String name, String track) {
        this(name, track, 0);      // must be first
    }
}

9. toString() — your object, printed nicely

By default, printing an object shows something like StudentRecord@6d06d69c (class name + memory hash). Override toString() to return a readable description; Java calls it automatically whenever the object is used where text is expected.

Java
@Override
public String toString() {
    return String.format("%s [%s] score=%d", name, track, score);
}

System.out.println(s1);          // Amara [AI-Driven Java] score=74
String label = "Top: " + s1;    // concatenation also calls toString()
ℹ️ @Override

An annotation telling the compiler "I intend to replace a method inherited from a parent class" (here, Object.toString()). If you misspell the method, the compiler catches it. Inheritance is Session 9 — for now, just use it on toString().

10. Encapsulation — private fields + accessors

Encapsulation means hiding an object's data and exposing only controlled operations. Make fields private; provide getters to read and, where it makes sense, setters (with validation) to change.

Java
class BankAccount {
    private double balance;                    // no outside code can set this directly

    public double getBalance() {               // controlled read
        return balance;
    }

    public void deposit(double amount) {       // controlled write, with a rule
        if (amount > 0) balance += amount;
    }
}

acc.balance = -999;      // COMPILE ERROR: balance has private access
acc.deposit(-999);       // allowed to try, but the method refuses
💡 Why bother?

A public field can be set to anything by anyone, anywhere — the "global data problem" from Session 1, in miniature. A private field with a validating method guarantees the object can never enter a broken state.

IntelliJ generates getters/setters for you: Alt+Insert (⌘+N on macOS) → Getter and Setter.

11. Stack & Heap Layout

Revisiting Session 2's memory picture, now with objects:

MemoryBankAccount ada = new BankAccount("Ada", 100);
        STACK (per method call)            HEAP (all objects)
   ┌───────────────────────────┐     ┌──────────────────────────────┐
   │ ada  ──────────────────────────▶│ BankAccount                  │
   │      (holds an address)   │     │   owner  = "Ada"  ───────────┼──▶ "Ada"
   │ amount = 50.0 (a local)   │     │   balance = 100.0            │
   └───────────────────────────┘     └──────────────────────────────┘
📖 In words

The variable ada lives on the stack and holds only an address. The actual BankAccount — its owner and balance — lives on the heap. Primitive locals like amount sit on the stack directly. When a method returns, its stack frame is discarded; heap objects survive until nothing references them, then the garbage collector reclaims them.

⚠️ == on objects compares addresses

a == b is true only if a and b point at the same object. To compare contents, write an equals method (Session 9) — exactly why you use str.equals(...) for text.

12. Common Pitfalls

🚨 Forgetting new

BankAccount a; then a.deposit(10); → the field is null → NullPointerException. You must a = new BankAccount(...); first.

🚨 Giving a constructor a return type

public void BankAccount(...) { } is not a constructor — it is an ordinary method that happens to be named like the class, so Java still uses the hidden default constructor. Constructors have no return type, not even void.

🚨 Shadowing a field by re-declaring it

this.balance = balance; ✅   vs   double balance = balance; ❌ (creates a new local, leaves the field at 0).

🚨 Printing instead of returning

A grade() that System.out.printlns cannot be used in if (s.grade().equals("A")). Return the value.

13. Executive Quick-Recap & Cheat Sheet

⚡ The 30-Second Mental Model

A class is a blueprint: fields (state) + methods (behavior). new builds an object on the heap and returns a reference. A constructor initialises it; this means "this object". Make fields private and expose methods (encapsulation). Override toString() to print nicely. Overloading = same name, different parameter lists.

Core Syntax at a Glance

Java Cheat Sheet
public class Product {
    private String name;          // fields (private)
    private double price;

    public Product(String name, double price) {   // constructor
        this.name = name;
        this.price = price;
    }

    public double getPrice() { return price; }    // getter

    public void applyDiscount(double pct) {        // behavior + validation
        if (pct > 0 && pct < 100) price -= price * pct / 100;
    }

    @Override
    public String toString() {
        return String.format("%s ($%.2f)", name, price);
    }
}

Product p = new Product("Hub", 34.99);
p.applyDiscount(10);
System.out.println(p);            // Hub ($31.49)

Plain-English Glossary

Class

A blueprint defining the fields and methods every object of that type will have.

Object / instance

A concrete thing built from a class with new, holding its own field values.

Field

A variable declared in the class body; each object has its own copy.

Constructor

A special no-return method named like the class, run once by new to set the object up.

this

A reference to the object the current method is running on.

Reference

A variable holding the address of a heap object (or null).

Overloading

Multiple methods (or constructors) with the same name but different parameter lists.

Encapsulation

Hiding fields (private) and exposing controlled methods.

Getter / setter

Methods that read / write a private field, the setter usually validating first.

toString()

A method returning an object's text form; called automatically on print and concatenation.

❓ Q1: What is the difference between a class and an object?
Answer: A class is the blueprint written once in code; an object is a concrete instance created at runtime with new, holding its own field values. One class, many objects.
❓ Q2: Car a = new Car(); Car b = a; b.speed = 90; — what is a.speed?
Answer: 90. b = a copies the reference, so a and b point at the same object.
❓ Q3: Why is public void BankAccount(String o) { } a bug?
Answer: The void makes it an ordinary method, not a constructor. Java then supplies its own empty default constructor, and your setup code never runs. Constructors have no return type.
❓ Q4: You call a method on a variable and get NullPointerException. What went wrong?
Answer: The variable holds null — no object was assigned. Create one with new before calling methods on it.
