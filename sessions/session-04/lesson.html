🧠 Memory Booster: The 3 Pillars of Week 1

You have covered tremendous ground in just 3 sessions! Let's connect the three foundational pillars before debugging today's workshop:

  • Pillar 1 (Platform): Your Java code compiles via javac into universal Bytecode (.class) that executes on any operating system equipped with a JVM.
  • Pillar 2 (Data): Variables live in RAM. Primitive variables hold their raw bits directly; Reference variables (Strings) hold memory pointers to objects on the heap.
  • Pillar 3 (Flow): By default, execution is linear. Branching (if/else, switch) chooses which path to take, and loops (for, while, do-while) repeat actions until a condition changes.

⚠️ Two String gotchas

1. Index out of range throws StringIndexOutOfBoundsException. Valid indexes are 0 to s.length() - 1.
2. s.toUpperCase(); on its own does nothing useful — you must capture the result: s = s.toUpperCase();.

4. Four Classic Algorithmic Loop Patterns

Every software engineer uses these four loop design patterns daily:

  1. The Accumulator (Summing / Running Totals)

    Initialize a sum variable to 0 before the loop; add to it on every iteration:

    int total = 0;
for (int i = 1; i <= 100; i++) {
    total += i; // 1 + 2 + 3 + ... + 100 = 5050
}
  2. The Counter / Filter

    Count items that satisfy a specific condition:

    int passes = 0;
// if (score >= 50) passes++;
  3. The Sentinel / Early Exit Flag

    Search for an item or verify a condition, breaking out as soon as a mismatch occurs:

    boolean found = false;
for (int i = 2; i * i <= n; i++) {
    if (n % i == 0) { found = true; break; }
}
  4. Digit Extraction via Modulus & Division

    Extract individual digits from right to left:

    while (num > 0) {
    int lastDigit = num % 10; // Grabs last digit
    num = num / 10;           // Drops last digit
}

5. The Professional Debugging Playbook

🚨 Bug 1: Integer Division Sneak Attack

double discount = 15 / 100 * price; // BUG: 15 / 100 is 0! Discount is always $0.00!
Fix: Use decimal literals: 15.0 / 100.0 * price or 0.15 * price.

🚨 Bug 2: The Semicolon Trap on Control Statements

if (score >= 50); // BUG: The semicolon immediately terminates the if!
{ System.out.println("Passed!"); } // This block now ALWAYS runs!
Fix: Never put a semicolon directly after the parenthesis of an if, for, or while header.

🚨 Bug 3: String Comparison with ==

if (input == "YES") // Checks if memory pointers match, NOT text!
Fix: Always use if (input.equals("YES")) or if (input.equalsIgnoreCase("YES")).

Reading a stack trace (when the program crashes while running)

A compile error stops javac. A runtime exception happens while the program runs and prints a stack trace. Read it top-down:

Console
Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Averager.main(Averager.java:8)
  • java.lang.ArithmeticException — the kind of problem.
  • : / by zero — the detail: you divided by zero.
  • Averager.java:8 — the exact file and line to open. Start here.

Common Week 1 exceptions: ArithmeticException (integer / or % by zero), InputMismatchException (Scanner.nextInt() got non-numeric text), StringIndexOutOfBoundsException (bad charAt/substring index), NullPointerException (using a variable that holds null). Full guide: Reading Error Messages.

6. Mental Code Tracing: The Trace Table Method

When a loop is misbehaving, don't guess — draw a Trace Table on paper. The method: one column per variable (plus the condition), one row per pass. After each line, write the new value. Plain-English Master Glossary

JDK / JRE / JVM

JDK creates code (compiler); JRE provides standard libraries; JVM executes universal bytecode on CPU hardware.

Stack vs. Heap

Stack holds active method frames and primitive variables; Heap holds dynamic reference objects (Strings, class instances).

Widening vs. Narrowing

Widening converts smaller types to larger types safely; Narrowing forces larger types into smaller types, truncating extra data.

Short-Circuit Evaluation

Logical optimization where && stops if first condition is false, and || stops if first condition is true.

Off-by-One Error (OBOE)

A common loop logic bug where the loop iterates one time too many or one time too few (e.g. <= 10 vs < 10).

Tracing Table

A step-by-step diagnostic chart tracking variable values across each iteration of a loop to verify algorithm correctness.

Test your comprehensive Week 1 knowledge with these diagnostic self-checks:

❓ Question 1: If a user enters an input through a loop that must run at least once to display the prompt, which loop construct is mathematically best?
Answer: The do-while loop! Because its condition check sits at the bottom (exit-controlled), the prompt and input capture are guaranteed to execute at least once without redundant code outside the loop.
❓ Question 2: Why will `String a = "test"; String b = new String("test"); (a == b)` evaluate to `false`?
Answer: The == operator compares object memory addresses (pointers). Because `b` was created with `new`, it resides at a different heap memory address. Always use a.equals(b) to compare the actual character contents.
❓ Question 3: What is the resulting type and value of `5 + 10 + "Java" + 5 + 10`?
Answer: "15Java510"! Left-to-right evaluation: 5 + 10 performs numeric addition (15). Then 15 + "Java" concatenates to "15Java". From then on, the remaining numbers are treated as strings and concatenated one by one.
