3. Worked Example: All Together

Payment is an abstract class (shared settle(), per-type fee()). Refundable is a separate capability only some payments have. PaymentException handles failure. The driver loop names none of the concrete types.

JavaPaymentSystem.java
class PaymentException extends Exception {
    PaymentException(String msg) { super(msg); }
}

interface Refundable {
    void refund(double amount) throws PaymentException;
}

abstract class Payment {
    protected double amount;
    protected boolean settled = false;
    Payment(double amount) { this.amount = amount; }

    abstract double fee();

    final void settle() throws PaymentException {
        if (amount <= 0) throw new PaymentException("amount must be positive");
        settled = true;
        System.out.printf("%s settled $%.2f (fee $%.2f)%n",
                getClass().getSimpleName(), amount, fee());
    }
}

class CardPayment extends Payment implements Refundable {
    CardPayment(double amount) { super(amount); }
    @Override double fee() { return amount * 0.029 + 0.30; }
    @Override public void refund(double refundAmount) throws PaymentException {
        if (!settled) throw new PaymentException("cannot refund an unsettled payment");
        if (refundAmount > amount) throw new PaymentException("refund exceeds original");
        System.out.printf("Card refunded $%.2f%n", refundAmount);
    }
}

class CashPayment extends Payment {          // NOT Refundable
    CashPayment(double amount) { super(amount); }
    @Override double fee() { return 0; }
}

public class PaymentSystem {
    public static void main(String[] args) {
        Payment[] payments = { new CardPayment(100), new CashPayment(50), new CardPayment(-5) };
        for (Payment p : payments) {
            try {
                p.settle();
                if (p instanceof Refundable r) r.refund(25);
            } catch (PaymentException e) {
                System.out.println("FAILED: " + e.getMessage());
            }
        }
    }
}
Output
CardPayment settled $100.00 (fee $3.20)
Card refunded $25.00
CashPayment settled $50.00 (fee $0.00)
FAILED: amount must be positive

4. Refactoring an instanceof Ladder to Polymorphism

JavaBefore — brittle
double area(Object shape) {
    if (shape instanceof Circle c)      return Math.PI * c.r * c.r;
    else if (shape instanceof Square s) return s.side * s.side;
    else if (shape instanceof Rect r)   return r.w * r.h;
    else throw new IllegalArgumentException("unknown shape");
}
// every new shape edits this method
JavaAfter — open for extension
interface Shape { double area(); }

class Circle implements Shape { public double area() { return Math.PI * r * r; } }
class Square implements Shape { public double area() { return side * side; } }

double area(Shape shape) { return shape.area(); }   // never changes again

The rule: when you find yourself asking "what type is this object?", the answer usually belongs inside the object as an overridden method.

5. Week 3 Debugging Playbook

🚨 @Override compile error

Your "override" has a different signature. Fix the parameter types / name — it was silently becoming a new, never-called method.

🚨 "does not override abstract method X"

A concrete class left an abstract / interface method unimplemented. Implement it (and mark it public for interface methods).

🚨 ClassCastException after instanceof-free cast

Guard the cast: if (obj instanceof Target t) { ... }.

🚨 "unreported exception X; must be caught or declared"

You called a method that throws a checked exception. Wrap it in try/catch, or add throws X to your method.

🚨 "exception X has already been caught"

A broad catch (Exception e) is before a narrower one. Reorder: specific first.

🚨 Empty catch hiding a real bug

Always log or handle. A swallowed NullPointerException can waste hours.

7. Week 3 Executive Cheat Sheet

⚡ The Week 3 Grand Mental Model

Model "is-a" families with inheritance (an abstract base for shared state + demanded methods). Model capabilities with interfaces a class can implement many of. Let polymorphism replace type-checking ladders. Handle failure with exceptions: checked for expected external problems, unchecked for bugs, try-with-resources for cleanup, custom types for your domain's failures.

Plain-English Master Glossary (Week 3)

Inheritance / super

Reuse + extend a parent; super(...) its constructor, super.m() its method.

Overriding / dynamic dispatch

Same signature in a subclass; the real type's version runs at run time.

abstract class / method

No instances; a body-less method every concrete subclass must implement.

interface / implements

A contract; a class fulfils many. default methods add shared bodies.

Comparable

compareTo defines a sort order (neg/0/pos).

lambda / functional interface

args -> body for a one-abstract-method interface.

Checked vs unchecked

Must handle vs optional; external failure vs programming bug.

try / catch / finally

Run risky code; handle a type (specific first); always-run cleanup.

try-with-resources

Auto-closes any AutoCloseable declared in the header.

Custom exception

Your class extending Exception / RuntimeException.

❓ Q1: A class needs shared state AND to be one of several unrelated capabilities. What do you use?
Answer: Extend an abstract class for the shared state, and implements one or more interfaces for the capabilities.
❓ Q2: Your driver loop has if (x instanceof A) ... else if (x instanceof B) .... What's the smell, and the fix?
Answer: Type-checking that belongs inside the objects. Give A and B a common interface method and call it polymorphically.
❓ Q3: When should a failure be a checked exception vs unchecked?
Answer: Checked for expected, recoverable external problems the caller should handle. Unchecked for programming bugs / bad arguments the code should prevent.
❓ Q4: @Override gives a compile error. What does that tell you?
Answer: You are not actually overriding anything — the signature doesn't match a superclass/interface method. Fix the name or parameters.
