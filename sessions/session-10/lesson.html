Session 10: Interfaces & Nested Classes

An interface is a promise: "any class that implements me can do X". It lets unrelated classes be used interchangeably — a SalariedEmployee, a Contractor, and an Invoice can all be "things to pay". Then we look at classes defined inside other classes, ending with a first taste of lambdas.

🧠 Memory Booster: Flashback to Session 9
  • Abstract classes (S9): a base type that can't be instantiated and can demand methods. An interface takes that idea further — pure contract, and a class can have many.
  • Polymorphism (S9): one Shape reference, many shape objects. Interfaces give you the same power across classes that share no common ancestor.
  • @Override (S5, S9): you write it on every method that fulfils an interface too.

1. What is an Interface?

An interface lists method signatures with no bodies — a capability, not an implementation. A class that implements the interface promises to provide every one of those methods.

Java
public interface Payable {
    double calculatePay();          // no body — every implementer must supply one
}
🔌 Analogy: the wall socket

A power socket is an interface: "provide a plug of this shape and I'll give you 240V". A lamp, a laptop charger, and a kettle are completely different devices, but because they all implement the plug contract, the socket works with any of them — and with devices that don't exist yet.

2. Implementing an Interface

Java
class SalariedEmployee implements Payable {
    private final double annual;
    SalariedEmployee(double annual) { this.annual = annual; }
    @Override public double calculatePay() { return annual / 12; }
}

class Contractor implements Payable {
    private final double rate, hours;
    Contractor(double rate, double hours) { this.rate = rate; this.hours = hours; }
    @Override public double calculatePay() { return rate * hours; }
}

Interface methods are implicitly public and abstract; your implementing methods must be public. Forget to implement one and the class won't compile (unless the class is itself abstract).

3. Programming to an Interface

The payoff: write code against the interface type, and it works with every current and future implementer.

JavaPayrollDemo.java
Payable[] toPay = {
    new SalariedEmployee(90000),
    new Contractor(45, 80),
    new Invoice(1250.50)          // not an employee — still Payable
};

double total = 0;
for (Payable p : toPay) {
    total += p.calculatePay();    // the real class's version runs
}
// total = 7500.00 + 3600.00 + 1250.50 = 12350.50
💡 The design rule

"Program to an interface, not an implementation." Declare variables, parameters, and return types as the interface (List, Payable), so callers aren't locked to one concrete class.

4. Multiple Interfaces

A class extends only one class but can implement many interfaces — this is how Java gets the flexibility of multiple inheritance without its headaches.

Java
interface Printable { void print(); }
interface Saveable  { void save(); }

class Report implements Printable, Saveable {
    @Override public void print() { System.out.println("printing..."); }
    @Override public void save()  { System.out.println("saving...");   }
}

// A Report is-a Printable AND a Saveable:
Printable p = new Report();
Saveable  s = new Report();

5. default & static Methods in Interfaces

Since Java 8, an interface may provide a default method — a body that implementers inherit unless they override it. Useful for adding a convenience method without breaking every existing implementer.

Java
public interface Payable {
    double calculatePay();

    default String payslip() {                 // implementers get this for free
        return getClass().getSimpleName() + ": $" +
               String.format("%.2f", calculatePay());
    }

    static Payable zero() {                     // a factory helper on the interface itself
        return () -> 0.0;
    }
}

6. Comparable — a Built-in Interface

To let Arrays.sort / Collections.sort order your objects, implement Comparable<T> and its one method compareTo: return a negative number if this is "less", 0 if equal, positive if "greater".

JavaSortableDemo.java
class Book implements Comparable<Book> {
    final String title;
    final int pages;
    Book(String title, int pages) { this.title = title; this.pages = pages; }

    @Override
    public int compareTo(Book other) {
        return Integer.compare(this.pages, other.pages);   // ascending by pages
    }
}

Book[] shelf = { new Book("Epic", 900), new Book("Short", 40), new Book("Novella", 150) };
Arrays.sort(shelf);   // -> [Short (40p), Novella (150p), Epic (900p)]
💡 Use the built-in comparators

Integer.compare(a, b), Double.compare(a, b), a.compareTo(b) for Strings — never a - b for compareTo (it can overflow for large ints).

8. Nested Classes

A class defined inside another class. Four flavours:

KindDeclaredSees outer instance fields?Typical use
static nestedstatic class Point { }NoA helper type that logically belongs to the outer class (e.g. Map.Entry).
inner (non-static)class Tagger { }YesA helper that needs the enclosing object's data. Created as outer.new Tagger().
localinside a methodThe method's final/effectively-final localsA one-method-only helper.
anonymousnew Runnable() { ... }YesA one-off implementation of an interface/abstract class, inline.
Java
public class NestedDemo {
    static class Point {                        // static nested
        final int x, y;
        Point(int x, int y) { this.x = x; this.y = y; }
    }

    private String label = "outer";
    class Tagger {                              // inner — can read 'label'
        String tag(String s) { return "[" + label + "] " + s; }
    }

    public static void main(String[] args) {
        Point p = new Point(3, 4);
        NestedDemo demo = new NestedDemo();
        NestedDemo.Tagger t = demo.new Tagger();   // inner needs an outer instance
        System.out.println(t.tag("hello"));         // [outer] hello
    }
}

Day to day you'll mostly write static nested classes and anonymous ones (or their lambda replacements).

9. Anonymous Classes & Lambdas

An anonymous class implements an interface right where you need it, without a separate named class:

Java
interface Greeter { String greet(String name); }

Greeter g = new Greeter() {
    @Override public String greet(String name) { return "Hi, " + name + "!"; }
};
System.out.println(g.greet("Ada"));        // Hi, Ada!

When the interface has exactly one abstract method (a functional interface), a lambda says the same thing far more compactly:

Java
Greeter g2 = name -> "Hey, " + name + ".";
System.out.println(g2.greet("Bode"));      // Hey, Bode.
ℹ️ This is a bridge to Session 14

Lambdas + functional interfaces power the Streams API you'll meet in Week 4. For now, just recognise x -> expression as "a tiny method with no name".

10. Common Pitfalls

🚨 Implementing method not public

Interface methods are public; your override must be too. double calculatePay() without public → "attempting to assign weaker access privileges".

🚨 Trying to instantiate an interface

new Payable() — no. You instantiate a class that implements it, or use an anonymous class / lambda.

🚨 Putting instance fields in an interface

An interface can only hold constants (public static final). If you need per-object state, that's an abstract class.

🚨 compareTo using a - b

Integer subtraction can overflow. Use Integer.compare(a, b).

🚨 Creating an inner class without an outer instance

A non-static inner class needs outer.new Inner(). If it doesn't use the outer object, make it static.

11. Executive Quick-Recap & Cheat Sheet

⚡ The 30-Second Mental Model

An interface is a contract of method signatures; a class implements as many as it likes and must supply every method (public). Program to the interface type for maximum flexibility. default methods add shared bodies. Comparable makes objects sortable. Nested classes: static nested (no outer link), inner (has one), anonymous (one-off implementation) — and a lambda replaces an anonymous class for single-method interfaces.

Core Syntax at a Glance

Java Cheat Sheet
interface Shape {
    double area();
    default String label() { return getClass().getSimpleName() + " " + area(); }
}

class Circle implements Shape {
    private final double r;
    Circle(double r) { this.r = r; }
    @Override public double area() { return Math.PI * r * r; }
}

class Square implements Shape, Comparable<Square> {
    private final double side;
    Square(double side) { this.side = side; }
    @Override public double area() { return side * side; }
    @Override public int compareTo(Square o) { return Double.compare(side, o.side); }
}

Shape[] shapes = { new Circle(2), new Square(3) };
for (Shape s : shapes) System.out.println(s.label());

Runnable r = () -> System.out.println("ran");   // lambda for a 1-method interface
r.run();

Plain-English Glossary

Interface

A contract of method signatures a class promises to implement.

implements

Keyword declaring a class fulfils one or more interfaces.

default method

An interface method with a body that implementers inherit unless overridden.

Comparable

Built-in interface; compareTo defines a natural ordering for sorting.

Program to an interface

Use the interface as the variable/parameter type, not a concrete class.

static nested class

A class inside another with no reference to an outer instance.

inner class

A non-static nested class bound to an outer object, able to use its fields.

anonymous class

A class with no name, defined and instantiated in one expression.

functional interface

An interface with exactly one abstract method — a lambda's target type.

lambda

args -> body — a compact anonymous method.

❓ Q1: How many interfaces can one class implement? How many classes can it extend?
Answer: Many interfaces; exactly one class.
❓ Q2: Can an interface have instance fields?
Answer: No. Only public static final constants. Per-object state means you want an abstract class.
❓ Q3: compareTo returns a negative number. What does that mean?
Answer: this object should sort before the argument (it is "less"). 0 = equal ordering; positive = after.
❓ Q4: When can a lambda replace an anonymous class?
Answer: When the target interface has exactly one abstract method (a functional interface), e.g. Runnable, Comparator, Greeter.
