3. Worked Example: It All Fits Together

A Gradebook holds an ArrayList of Student objects and computes statistics over them. Every Week 2 idea appears here.

JavaGradebook.java
import java.util.ArrayList;

class Student {
    private final String name;      // encapsulated + final
    private int score;
    Student(String name, int score) { this.name = name; this.score = score; }
    String getName() { return name; }
    int getScore()   { return score; }
    void adjust(int delta) { score += delta; }
    @Override public String toString() { return name + " (" + score + ")"; }
}

public class Gradebook {
    private final ArrayList<Student> students = new ArrayList<>();

    void add(Student s) { students.add(s); }

    double classAverage() {                     // accumulator over a collection
        if (students.isEmpty()) return 0;
        int total = 0;
        for (Student s : students) total += s.getScore();
        return (double) total / students.size();
    }

    Student topStudent() {                       // running-best over a collection
        Student top = students.get(0);
        for (Student s : students)
            if (s.getScore() > top.getScore()) top = s;
        return top;
    }

    public static void main(String[] args) {
        Gradebook gb = new Gradebook();
        gb.add(new Student("Ada", 82));
        gb.add(new Student("Bob", 74));
        gb.add(new Student("Cal", 91));
        gb.add(new Student("Dee", 68));

        System.out.printf("Class average : %.2f%n", gb.classAverage());   // 78.75
        System.out.println("Top student   : " + gb.topStudent());          // Cal (91)

        gb.topStudent().adjust(-50);     // returns a REFERENCE to Cal — really changes him
        System.out.println("After penalty : " + gb.topStudent());          // Ada (82)
    }
}
💡 The subtle bit

topStudent() returns a reference to the actual Student object, not a copy. Calling .adjust(-50) on it really lowers Cal's score to 41 — so the next call to topStudent() now finds Ada. References, not values.

4. Class Design Checklist

  1. What does one object represent? Name the class as a noun (Student, Invoice).
  2. What does it know? List the fields. Make them private. Mark those that never change final.
  3. How is it born? Write a constructor that leaves the object in a valid state (clamp/validate inputs).
  4. What can it do? Public methods for behaviour outside code needs; private helpers for the rest. Methods return results.
  5. Anything shared by all objects? A count, a rate, a constant → static (and final if constant).
  6. How should it print? Override toString().

5. OOP-Era Debugging Playbook

🚨 NullPointerException on an object you "made"

You declared the reference but never new'd it, or an array/list slot is still null. Trace back to where it should have been assigned.

🚨 "non-static ... cannot be referenced from a static context"

main is static and is calling an instance method/field directly. Make the target static, or create an object first.

🚨 "x has private access in Y"

Outside code is touching a private field. Add a getter/setter, or move the logic into the class.

🚨 ConcurrentModificationException

You called list.remove(...) inside a for-each over that list. Loop backwards by index, or collect then remove.

🚨 Two references, one object surprise

b = a for objects/arrays copies the address. Changing through b changes what a sees. If you need an independent copy, make one explicitly.

🚨 Comparing objects with ==

Use .equals() for String and wrapper values; Arrays.equals() for arrays. (Writing your own equals for custom classes is Session 9.)

7. Week 2 Executive Cheat Sheet

⚡ The Week 2 Grand Mental Model

Model the domain as classes (state + behavior, fields private). Build objects with new; variables hold references. Keep many objects in an array (fixed) or an ArrayList (growable). Share class-wide data with static, lock it with final. Organise files into packages; ship them in a JAR. Most new bugs are null, static-context, private-access, or two-references-one-object.

Plain-English Master Glossary (Week 2)

Object vs reference

The object lives on the heap; the variable holds its address. Assigning the variable copies the address, not the object.

Constructor

Runs at new time to set an object up; class name, no return type.

Overloading

Same method/constructor name, different parameter lists.

Array vs ArrayList

Fixed size + a[i] + .length vs growable + .get(i) + .size().

Wrapper / autobox

Integer for int; Java converts automatically for generic collections.

static

Belongs to the class — one shared copy, callable without an object.

final

Assign-once variable / non-overridable method / non-extendable class.

Access levels

public > protected > package-private > private.

Package

Named folder of classes; path matches name; import to use.

JAR

Zipped classes; executable if the manifest names a Main-Class.

❓ Q1: A method returns a Student from an ArrayList. You call a mutating method on the result. Does the list's object change?
Answer: Yes. The method returns a reference to the same object in the list, so mutating it changes what the list holds.
❓ Q2: When do you choose static for a field?
Answer: When the data describes the class as a whole (a total count, a shared rate/constant) rather than one object's state.
❓ Q3: list.size(), a.length, s.length() — which needs no parentheses?
Answer: a.length (array). It is a field. ArrayList.size() and String.length() are methods.
❓ Q4: Your static main calls process(), a non-static method, and won't compile. Two fixes?
Answer: Make process() static, or create an object and call obj.process().
