Start Here: How This Course Works

You are about to learn Java from absolute zero. This page explains how the course is organised, how to study each session, how to check your own work, and — most importantly — what to do when you get stuck (everyone does).

1. Who this course is for

This course assumes you have never written a line of code. You do not need any maths beyond basic arithmetic. You need a computer (Windows, macOS, or Linux), an internet connection to download tools once, and about 3–4 hours per week outside class.

💡 The one habit that matters

Type every example yourself. Do not copy-paste and do not just read. Your fingers learn syntax faster than your eyes do, and the small mistakes you make while typing are where the real learning happens.

2. Before Session 1: set up your machine

Go to the Environment Setup page and follow it end to end. You will install:

  • A JDK (Java Development Kit) — the compiler and tools that turn your code into a running program.
  • IntelliJ IDEA Community Edition — a free, professional code editor that catches mistakes as you type.

The setup page also has a troubleshooting section for the errors beginners hit most often ('javac' is not recognized, JAVA_HOME, PATH problems). If something breaks, that is the first place to look.

3. The rhythm of every session

Each session has the same six parts. Do them in order:

StepWhat it isWhy
1. Pre-Quiz 5 quick questions before you learn the topic. It is meant to be hard. It wakes up your curiosity and shows you what today unlocks. A low score here means nothing.
2. Lesson The main teaching page, with analogies, diagrams, and line-by-line code. This is the core. Read it slowly. Use the sticky menu on the left to jump around.
3. Class Tasks Three coding exercises: 🟢 Easy, 🟡 Medium, 🔴 Challenge. You practise each idea immediately, while it is fresh. Every task shows the exact output you should get.
4. Assignment A larger, real-world scenario to do on your own time. It proves you can combine the week's ideas without hand-holding.
5. Post-Quiz 8 questions after the lesson, including "what does this code print?". Confirms the concepts stuck. Aim for 70%+. If you score lower, re-read the flagged sections and retake it.
6. Solutions Full, commented reference answers for every task and assignment. For checking your work after you have genuinely tried. See the rule below.

4. How to use the solutions honestly

⚠️ The 20-minute rule

Do not open a solution until you have struggled with the problem for at least 20 minutes. Struggle is not wasted time — it is the moment your brain builds the connection. When you do look, read the whole solution, close it, and then retype it from memory. If you cannot, you have not learned it yet.

Every session links its solutions from the Class Tasks and Assignment pages. Each solution includes a short walkthrough and the exact console output, so you can compare byte for byte.

5. Using an AI tutor (ChatGPT, Copilot, IntelliJ AI)

This is an AI-driven course. AI tools are excellent tutors and dangerous crutches. The rule for Weeks 1–3:

  • Use AI to explain — "explain this error like I'm new", "why does this loop run forever?", "give me 3 practice problems on X".
  • Do not use AI to write your tasks and assignments for you. If you cannot explain every line you submit, it is not yours and you have not learned it.
  • Always verify. AI sometimes invents methods that do not exist or gives code far above your level. Check it against the lesson.

The AI Tutor Guide has ready-made prompt patterns and shows you how to catch a wrong answer. Every lesson also has a 🤖 Ask Your AI Tutor box with prompts tuned to that topic.

6. When you get stuck (a checklist)

  1. Read the error message. Really read it — the file name, the line number, the first line of the message. See Reading Error Messages.
  2. Fix only the first error. One mistake often causes ten error lines. Fix the top one and recompile.
  3. Check the usual suspects: a missing ;, a missing }, a capital letter in the wrong place, = where you meant ==.
  4. Trace it by hand. Write down each variable and update it line by line. The lesson pages show you how with "🧭 Trace it" tables.
  5. Ask your AI tutor to explain the error and your code — not to rewrite it.
  6. Ask your instructor or a classmate. Bring the exact error text and what you already tried.
