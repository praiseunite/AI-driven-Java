Reading Error Messages

Error messages are not the computer being rude — they are the computer telling you exactly what and where the problem is. Learning to read them is the single biggest speed-up in your first month. This page shows you how.

On this page

  • Two kinds of error
  • Reading a compile error
  • Fix the first error first
  • Reading a stack trace

Two kinds of error

Compile-time errorRuntime error (exception)
WhenWhen you run javac / press Run — before the program starts.While the program is running.
MeaningYour code is not valid Java. The compiler refuses to build it.The code was valid, but something went wrong as it executed (bad data, missing file, dividing by zero).
Looks likeHelloWorld.java:5: error: ';' expectedException in thread "main" java.lang.ArithmeticException: / by zero
Your jobFix the syntax the message points to.Read the exception type + the line number in your file, then guard against that case.

Reading a compile error

Every javac error has the same shape:

Terminal
Receipt.java:7: error: ';' expected
        System.out.println("Total")
                                   ^
1 error
PartWhat it tells you
Receipt.javaWhich file.
:7Which line. Start here.
error: ';' expectedWhat is wrong: a semicolon is missing.
The ^ caretPoints at (or just after) the spot. Here: end of line 7 — add ;.
1 errorHow many problems the compiler found this round.
💡 The message points at the symptom, not always the cause

A missing } on line 12 can make the compiler complain about line 20. If line 20 looks fine, check the lines above it for an unclosed brace, bracket, or quote.

Fix the first error first

One small mistake often produces a wall of red. Do not read all of it. Scroll to the top, fix that one error, then compile again. Very often ten errors become zero.

⚠️ Don't panic-edit

Changing five things at once and re-running means you no longer know which change helped. One change, one recompile.

Reading a stack trace (runtime exception)

When a running program crashes, Java prints a stack trace:

Terminal
Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Salary.calculateDaily(Salary.java:14)
    at Salary.main(Salary.java:6)

Read it top to bottom:

  1. java.lang.ArithmeticException — the type of problem. This one means bad arithmetic.
  2. : / by zero — the detail. You divided by zero.
  3. at Salary.calculateDaily(Salary.java:14) — where it actually blew up: line 14. Look here first.
  4. at Salary.main(Salary.java:6) — who called that code: line 6 called calculateDaily. This is the trail of how you got there.
💡 Find your own file name

A long trace may have many at ... lines from Java's own libraries. Scan for the first line that names your file (Salary.java) — that is the line you can fix.

Common message decoder

MessageUsually meansFix
';' expectedMissing semicolon at end of a statement.Add ; where the caret points.
cannot find symbolA name you used is not declared, is misspelled, or has the wrong capitals.Check spelling/case; declare the variable; add the import.
incompatible types: double cannot be converted to intAssigning a wider value into a narrower type.Change the variable's type, or cast on purpose: (int) x.
reached end of file while parsingA } is missing.Count your braces; let the IDE auto-indent to reveal the gap.
class X is public, should be declared in a file named X.javaFile name ≠ public class name.Rename the file to match exactly.
NullPointerExceptionYou used a variable that holds null (no object) as if it held one.Check what was never assigned / what a method returned. Guard with an if.
ArrayIndexOutOfBoundsException: 5Asked for index 5 of an array that does not have one (valid indexes are 0..length-1).Fix the loop bound (< vs <=) or the index.
InputMismatchExceptionScanner.nextInt() got text that is not a number.Validate input, or read with nextLine() and convert.
Could not find or load main classRan java File.class, wrong folder, or no main.java File (no extension), from the folder holding the .class.
error: <identifier> expectedCode placed directly in the class body instead of inside a method.Move executable statements inside main (or another method).

A calm method for any error

  1. Stop. An error is information, not failure.
  2. Find the first error (compile) or the first line naming your file (runtime).
  3. Read the file name and line number. Open that line.
  4. Read the words of the message. Translate them using the decoder above.
  5. Make one change.
  6. Recompile / rerun.
  7. Still stuck after 15 minutes? Ask your AI tutor to explain the error (not to rewrite your code) — see the AI Tutor Guide — then your instructor.
