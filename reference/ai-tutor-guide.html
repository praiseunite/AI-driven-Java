Using an AI Tutor Well

This is an AI-driven course, and you will use tools like ChatGPT, GitHub Copilot, and IntelliJ's AI Assistant throughout your career. Used one way, they make you faster and sharper. Used another way, they quietly stop you from learning. This page is the difference.

The core principle

💡 Use AI to understand, not to produce

If AI explains a concept, shows you an example you then rebuild yourself, or helps you read an error — you are learning. If AI writes your task or assignment and you submit it, you have learned nothing and it will show in the next quiz, the exam, and your first job interview.

A simple test before you paste anything AI gave you: can you explain every single line out loud? If not, ask it to explain, or to simplify to your level, until you can.

Good uses vs bad uses (Weeks 1–3)

✅ Do this❌ Not yet
"Explain what static means to someone who just started Java.""Write the Session 2 assignment for me."
"Here is my error message and my code. What does the error mean?""Fix my code" (without trying to read the error yourself first).
"Give me 5 practice problems on for loops, easy to hard, no solutions yet.""Give me the answers to these practice problems."

Prompt patterns that work

Always tell it who you are and what you want back.

🧩 Explain a concept

"I'm a complete beginner learning Java. Explain [the difference between == and .equals()] using a plain analogy and one tiny code example. Keep it under 150 words."

🐞 Understand an error

"I'm new to Java. I ran this code [paste code] and got this error [paste the full error]. Explain what the error means in plain English and point me to the line to look at. Do not rewrite my program."

🧭 Trace / predict output

"Trace this code line by line. Show a table with each variable's value after every line, and the final printed output. [paste code]"

🏋️ Generate practice (not answers)

"Give me 6 practice exercises on Java switch statements, ordered easy to hard. Only the problem statements and expected output — no solutions. I'll ask for hints if I need them."

🔍 Review your work (after you finish)

"I finished this exercise myself [paste code]. It works. As a mentor for a beginner, point out naming, formatting, or clarity I could improve — but only using concepts a Week 2 Java student would know."

How to catch a wrong answer

AI is confident even when wrong. Verify with these steps:

  1. Run it. The compiler and the output are the truth. If AI's code does not compile or prints the wrong thing, AI was wrong.
  2. Check it against the lesson. If the lesson taught printf and AI uses String.format with a syntax you have not seen, pause and ask why.
  3. Watch for "too advanced". Streams, lambdas, var, records in Week 1 are a red flag that the answer is above where you are — ask for a beginner version.
  4. Ask it to double-check itself: "Are you sure that method exists in Java 25? Show me the official signature."
  5. Cross-check the API in the official Java 25 documentation.

Hallucinated APIs — a real example

AI sometimes invents methods that sound plausible but do not exist, e.g. myString.reverse() (there is no such method on String) or Scanner.nextChar() (does not exist). The give-aways:

  • Your IDE underlines it red: "cannot find symbol".
  • javac refuses to compile it.
  • You cannot find it in the official docs.

When this happens, tell the AI: "That method doesn't compile — 'cannot find symbol'. What's the correct way in standard Java 25?"

Academic honesty

⚠️ Submitting AI work as your own is plagiarism

Assignments are graded to measure your understanding. If you use AI to help you learn a concept and then write the assignment yourself, that is learning. If you paste an AI-generated assignment, that is misconduct under Aptech's academic policy — and your instructor can tell, because they will ask you to explain it.

When in doubt, keep a note of how you used AI ("asked it to explain recursion, then wrote my own version"). Being able to describe your process is the honest path.
